## ③ 通知状态机（已读 ≠ 已修复）

1. 打开「通知中心」。
2. 表头应有「处理状态」列；新通知显示「待处理」。
3. 点「认领」→ 该行变「处理中」；点「标记已修复」→ 变「已修复」。

通过标准：状态按 待处理 → 处理中 → 已修复 变化，且刷新页面后仍是新状态。

## ⑤ AI 未命中问题清单

4. 页面下方「未命中问题（补知识库用）」表格出现该问题原文。

通过标准：拒答 + 清单里能看到这条问题。

## ⑧ AI 问答（真实模型 + 语义检索 + 引用）

1. 确认本机 embedding 服务：`curl -s http://127.0.0.1:41291/health` → `loaded:true`（可选组件，见 `tools/embedding-service/README.md`）。
2. 打开「AI 客服」，看「状态」：对话模型 `deepseek-v4.1-flash`、嵌入模型 `bge-small-zh-v1.5`、
   检索方式「语义（向量）」、就绪「是」。
3. 先在「FAQ 知识库」建一条问答（例：问「运费怎么算」，答「满 99 元免运费，偏远地区另计」）。
4. 重建索引（一次性）：
   ```bash
   curl -X POST 'http://127.0.0.1:41280/admin/v1/ai/semantic/reindex?kind=FAQ' \
     -H "Authorization: Bearer <token>"
   ```
5. 回到「AI 客服」→ 提问「运费怎么算？」。

通过标准：
- 回答由真实模型组织（不是把片段原样拼起来），引用来源有 sourceId + 相关度（本机实测 0.777）+ 片段；
- 无关问题返回「未命中/转人工」，不编答案；
- 模型不可达时 503 `AI_CHAT_FAILED`；embedding 不可达时 503 `AI_EMBEDDING_*`，都不伪装成“没有答案”。

## ⑨ 门店管理（新增）

1. 打开「交易 → 门店管理」。
2. 点「新建门店」→ 点编码旁的「生成」→ 选市场 → 填名称/地址 → 保存。
3. 在列表里点该门店的状态开关 → 确认停用。

通过标准：
- 列表出现新门店，编码形如 `STORE-…`；
- 停用后状态变为「已停用」，刷新仍保持；「全部状态」筛选能分别看到营业中/已停用；
- 同一编码再建一次 → 明确报「门店编码已存在」；
- 顾客端结算页的自提门店列表不再出现已停用门店。

## ⑩ 促销完善

1. 打开「交易 → 促销管理」。
2. 在促销活动表点任一行「复制为草稿」→ 列表出现「…（副本）」且状态为草稿。
3. 点该草稿「编辑」→ 改活动价/时间 → 保存 → 点「启用」。
4. 对进行中的活动点「结束」→ 确认。

通过标准：
- 编辑只对草稿可用（后端也会拒绝改进行中的活动）；
- 启用/结束都有二次确认，结束后不可再启用（只能复制）；
- 满减/满折规则点「编辑」时，**已选范围项仍然在**（此前保存会清空）；
- 规则编码点「生成」不会再撞已存在的编码。

## ⑬ 金额精度（按币种小数位）

1. 打开任意带金额的页面（订单/商品/促销/成本）。
2. 把某市场币种改成 JPY（0 位）或 KWD（3 位）后，查看价格显示与输入框精度。
3. 接口自检：
   ```bash
   curl -s http://127.0.0.1:41280/api/v1/currencies/precision
   ```
   应返回 `JPY=0`、`KWD=3`、`default=2`，且 `TWD/HUF=2`（不是 0）。

通过标准：
- 页面不再出现 `19.90` 这类固定两位的日元显示（应为 `¥1234`）；
- 商品改价、退款金额、促销价输入都按币种精度换算，不再写死 `/100`；
- 后端 `Money.toMajor/parseMajor` 对超出精度的小数直接报错（不静默截断）。

## ⑭ 汇率（阶段 1）

1. 打开「系统 → 汇率」。
2. 新增 `USD → CNY`，汇率 `7.2`，生效时间选当前。
3. 在「精确换算」输入 `10000`（USD 分）→ 选 USD → CNY → 换算。

通过标准：
- 结果显示 `720.00 CNY`（100.00 USD × 7.2），使用汇率为 7.2；
- 找不到币种对时明确报 `EXCHANGE_RATE_NOT_FOUND`，不会按 1:1 兜底；
- 只有反向汇率时显示「反向推导」，结果仍正确；
- 删除汇率后同一次换算立即失败（历史订单不受影响）；
- 下单后打开订单详情：显示「汇率快照」（CNY 订单为 1.0，基准总额=订单总额）；
  非基准币种且没有汇率时显示「未快照」，并可在审计里看到 `ORDER_FX_RATE_MISSING`，
  **不会**把缺失当成汇率 1。

## ⑮ 门店软删除

1. 「门店管理」→ 对一家**未绑定员工**的门店点「删除」并确认。
2. 状态筛选切到「已删除」→ 点「恢复」。

通过标准：
- 删除后默认/营业/停用列表都不再出现该门店，自提门店列表也不出现；
- 「已删除」筛选能看到并恢复；恢复后仍是停用状态；
- 仍绑定员工的门店删除会被拒绝（`STORE_HAS_STAFF`）；
- 已删除门店不能编辑/切换营业状态（`STORE_DELETED`）。
