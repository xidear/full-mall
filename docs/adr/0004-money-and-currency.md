# ADR-0004: 金额、币种与汇率快照

- 状态：Accepted
- 日期：2026-10-18

## 背景

多市场、多币种、折扣、税费、退款和分账场景下，浮点金额会产生精度和审计问题；汇率变化会导致订单金额与展示金额不一致。

## 决策

- 所有金额使用 `bigint` 存储最小货币单位（人民币为分），并单独存储 ISO 4217 币种代码。
- 禁止使用 `float`/`double` 表示金额。
- 订单、支付、退款保存价格、税费、折扣、运费和汇率快照。
- 汇率由 `ExchangeRateProvider` 提供；下单时快照，不在展示时回算历史订单。
- 每个市场配置舍入规则（四舍五入、银行家舍入等）和最小价格单位。
- 跨币种退款按原支付币种和原金额处理；如需换汇，单独记录。

## 后果

- 需要统一的 `Money` 值对象和数据库约束。
- 报表需要明确币种口径，不能直接相加不同币种。
- 前端只做展示格式化，不做金额计算。

## 替代方案

- `decimal`：可行，但 Java/JS 边界和序列化更容易出错；统一整数分更简单。
