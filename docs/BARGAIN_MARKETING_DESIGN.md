# 砍价营销（假砍价）设计草案 v0

> 定性：**名义砍价、实质拉新**。属合法营销，但**不能做成抽奖或 0 元购**。
> 状态：草案，待确认参数后实施（OPEN_ITEMS D13）。

## 1. 规则（建议默认值）

| 参数 | 默认 | 约束 |
|---|---|---|
| `floorPrice`（最低成交价） | **手填**，界面给"推荐值"与"一键采用" | **不做成本硬下限**；低于成本需显式勾选"允许亏本引流"并填原因 |
| 最大优惠 | 原价 − floorPrice | 由 floorPrice 推导，不允许手填超出 |
| 最少助力人数 | 5 | 3..30 |
| 单次砍价额 | 固定或区间（如 5~20 元） | 总额 ≤ 最大优惠，最后一刀自动收敛到 floorPrice |
| 有效期 | 24 小时 | 12..72 |
| 达成后 | **必须支付 floorPrice** | 不是免费领 |

## 2. 数据模型

```
bargain_activity (id, sku_id, floor_price, max_cut, min_helpers, cut_min, cut_max,
                  expires_hours, status, starts_at, ends_at)
bargain_session  (id, activity_id, member_id, current_price, helpers, status,
                  expires_at, order_id)
bargain_help     (id, session_id, helper_member_id, cut_amount, created_at,
                  UNIQUE(session_id, helper_member_id))   -- 助力人去重
```

## 3. 并发与幂等

- 砍价用 `SELECT ... FOR UPDATE` 锁 session；每人只能助力一次（唯一索引兜底）；
- 最后一刀 `min(cut, current_price - floor_price)`，**不允许低于底价**；
- 达成写 `status=READY` 并生成锁定价格；下单时校验收货地址与活动价一致；
- 过期未达成：`status=EXPIRED`，无扣款（未支付）。

## 4. 合规红线（写进代码与页面）

| 禁止 | 原因 |
|---|---|
| 显示虚假原价（先涨后降） | 《价格法》《明码标价规定》 |
| 未达成也收钱 | 构成欺诈 |
| 必须关注公众号/下载 App 才能继续砍 | 诱导分享，违反平台规则 |
| 0 元或 1 分购 | 不正当竞争风险 |
| 不公示中奖/助力规则 | 消费者知情权 |

页面必须明示：活动价、最低成交价、所需人数、截止时间、未达成处理方式。

## 5. 已确认（2026-10-19）

| 问题 | 决定 | 落地要求 |
|---|---|---|
| 底价怎么定 | **运营手填**；系统给"推荐底价 = 成本 × 1.05"与**一键采用** | 推荐值只做提示；**不设成本硬下限**——低价引流是合法策略，低于成本时必须显式确认并记录原因 |
| 是否限新客 | **不限新客**，所有会员都可发起 | 不加"首单"限制；防刷靠助力人去重与每人限次 |
| 达成后未支付 | **不立即释放库存**，等订单支付超时后再释放 | 复用现有订单超时释放任务；活动侧状态 `READY → EXPIRED`，不重复释放 |

### 实现要点（依据以上决定）

1. **底价校验**：只校验 `floorPrice >= 1 分`；`floorPrice < 成本` 时要求 `allowBelowCost=true` + `reason`，
   并在活动页与报表标注"引流价/负毛利"（审计留痕），**不阻止保存**；
2. **库存**：达成时按正常下单流程**预占**（不做特殊逻辑），未支付就走订单超时释放；
   活动过期不额外调用释放，避免双重释放把库存加多；
3. **不区分新老客**，但同一会员同一活动只能发起一次（唯一索引）。

### 待补（实现前需要确认）

- 成本从哪来：当前 `sku` 无成本字段（A8 待补），底价推荐需要先有成本；
  过渡方案：成本未维护时**允许启用**，但必须显式确认"成本未知，毛利无法核算"；
  报表显示"成本未知"而不是 0；禁止静默按 0 计算。
