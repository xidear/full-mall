# 剩余工作收口计划（回归业务主线）

> 台账：`docs/OPEN_ITEMS.md`（132 条）。当前 ✅71 / ⚠️16 / ⬜45 / 🚫6。
> 原则：**先做能自证的功能，再做需要外部条件的；🚫 项单独讨论，不偷偷改口径。**

## 一、有意不做（6 条，需你确认是否维持）

| 编号 | 内容 | 当时的理由 | 如果要做，代价 |
|---|---|---|---|
| J1 | 线上匿名下单 | 大陆场景必须绑定真人；已由 OTP 访客 + 收银台代下单覆盖 | 风控与售后无法定责，不建议放开 |
| J2 | 客户与客服"同一身份" | 两套账号体系严格隔离（你明确要求） | 会导致权限串号，属安全红线 |
| J3 | 独立 `payment_sub_merchant` 表 | 全商城一个子商户号 | 多商户分账时才需要，改动涉及支付重构 |
| J4 | 手填 JSON 配置业务规则 | 全部结构化表单，JSON 由服务端生成 | 运营误填即线上事故 |
| J5 | 部分退款自动退券 | 同一张券可能被用两次（资损） | 需券级幂等与回滚设计，属独立项目 |
| J6 | 换货自动完成 | 无签收回调，无法确认顾客收货 | 需接入物流签收回调（依赖 D8） |

**我的建议**：J1–J4 维持不做；J5、J6 若客户坚持，作为独立需求立项（不能顺手加）。

## 二、可自主完成（无外部依赖，按优先级）

### 批次 1：收尾已有半成品（各 1–2 天量级）

| 编号 | 内容 | 验收标准 |
|---|---|---|
| C5 | 券模板编辑/停用 | 改面额/有效期后已发实例不受影响；停用后不可再领 |
| C6 | 券核销统计 | 领取率/核销率按模板统计，与订单核销记录一致 |

| M3 | 打包预设（永久/7 天/30 天） | 脚本生成三件套；7 天包启动显示剩余天数 |
