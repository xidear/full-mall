## 1. 语言与内容

| 问题 | 定案 | 理由 |
|---|---|---|
| 目标语言优先级 | **en → es → ar（RTL）→ fr → ru**；首发只做 en + es | 英文是默认内容语言（固定兜底），西语覆盖拉美/西班牙；ar 涉及 RTL，UI 成本单独排期 |
| 机翻能否直接上线 | **不能**：所有面向顾客的译文必须 `REVIEWED` 才能 `PUBLISHED` | 法律/支付/商品功效文案风险太高；人工成本用 TM 抵扣（命中不计费） |
| 商品图能否出境给第三方 AI | **允许，但按类目白名单**；人像/证件/地址类图片禁止外发 | PIPL 数据出境要求；白名单从"家居日用/标品"开始 |
| 视频是否必做 | **二期**：先图片（主图 + 详情图），视频在图片流水线稳定后接 | 视频按秒计费且审核成本高，先不阻塞主流程 |
| 单商品本地化预算上限 | **默认 200 分/每语言**（可配置），超限拒绝并告警 | 防止"上传即全语言批量生成"造成成本失控 |

## 2. 支付与结算

| 问题 | 定案 | 理由 |
|---|---|---|
| 服务商选哪家 | 不写死；`payment_provider_config` 支持随时切换，历史按版本路由 | 服务商是商务决策，代码不绑定 |
| 佣金/服务费费率 | **默认 0**，配置项 `app.supplier.settlement.commission-rate` | 无业务规则前不臆造 |
| 退款冲减口径 | 按**原单成本/原支付配置**回冲，不按当前值 | 保证历史对账稳定 |
| 子商户粒度 | **整个商城一个子商户** | 已按用户口径确认 |

## 3. 导出与性能

| 问题 | 定案 | 理由 |
|---|---|---|
| 异步导出文件保留期 | **7 天**（签名 URL 有效期 + 对象存储生命周期） | 平衡合规与可用性 |
| 每人并发/每日次数 | **并发 1、每日 20 次**，可配置 | 防止单账号拖垮 worker |
| 导出进度交互 | **轮询 + 指数退避**（1s→2s→5s→15s→60s），不做 WS | 任务级低频，WS 运维成本不划算 |
| 大表分区 | `stock_move`/`audit_event`/`pos_sale`/`orders` 按月 RANGE 分区，保留 24 个月 | 单表超过千万行后再分区成本很高 |

## 4. 媒体与存储

| 问题 | 定案 | 理由 |
|---|---|---|
| 图片快照存什么 | **绝对 http(s) URL**（已实现 `MediaUrlResolver`） | 域名变更、小程序要求、存储迁移 |
| 是否额外存 assetId | **存**：快照同时保留 `assetId`，迁移时可按它批量重写 URL | 绝对 URL 的迁移抓手，不影响现有规则 |
| 存储迁移策略 | 双读（旧 URL 可访问）+ 校验 hash + 切换 + 可回滚 | 避免断链 |

## 5. 审计

| 问题 | 定案 | 理由 |
|---|---|---|
| JaVers 连接问题 | **outbox + 单消费者**：业务同事务写 outbox，单线程用一条连接写 JaVers | 根因是库不接管连接生命周期；串行写入可接受且不阻塞业务 |
| 审计保留 | 24 个月，之后归档冷存储 | 合规留痕 + 成本控制 |
