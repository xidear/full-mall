## 0. 文档约定

- **必须（MUST）**：验收必须满足。
- **应该（SHOULD）**：默认满足，除非有明确理由。
- **可以（MAY）**：可选增强。
- 需求编号用于开发计划、测试用例和验收记录追溯。
- “演示模式”指 `demo` profile；“生产模式”指 `prod` profile。
- 生产模式缺少必需配置时必须**启动失败或明确报错**，禁止静默降级到 Mock。
- 价格、佣金、结算金额一律使用最小货币单位整数 + ISO 币种。

## 1. 目标与范围

### 1.1 目标

把现有商城从“可演示的垂直切片”推进为可运营的跨境商城平台：

- 自营商城 + 供应商代发 + 门店自提/门店收银 + 自营仓储 ERP。
- 线上会员、促销、支付、客服、多语言、多币种完整闭环。
- 供应商、客服、门店、运营的数据权限可审计、可配置。
- 管理后台可关闭子模块，关闭后对应 API/Web/登录不可用，但不影响支付回调等基础设施。
- 提供可版本化、可自动更新的供应商对接文档。

### 1.2 非目标

- 不做供应商侧复杂 ERP/OA；供应商只保留轻量订单、库存、结算、退货协同。
- 不做采购审批流；自营 ERP 需要采购单、到货预约、质检上架，但不引入多级审批。
- 不做银行卡收单资质、终端硬件认证、完整总账/税务申报。
- 不做 marketplace 分账、复杂 B2B 报价、完整 MRP。
- 不复制 CRMEB/ThinkPHP 代码；只借鉴产品策略与架构思想。

## 2. 代码复用、模型与权限架构

> 原则：所有需求先调研成熟 Java/开源方案，选型与理由记录在 `TECHNOLOGY_DECISIONS_V2.md`。字段级可见性不是硬性要求；不得把 ThinkPHP 的做法直接翻译成自研框架。

### 2.1 模型与 schema

**CR-001（MUST）** 生产 schema 以 Flyway 迁移为唯一版本来源；实体/模型只负责字段映射与校验一致性（Hibernate `ddl-auto=validate`），禁止 `ddl-auto=update` 上生产。

**CR-002（MUST）** 禁止在多个 Controller/Service 重复手写同一张表的列清单；列定义、DTO、OpenAPI、审计字段必须可追溯或自动校验一致。

**CR-003（MUST）** 新 CRUD/ERP 模块优先使用 Spring Data JPA/Hibernate 的成熟能力：`@Version` 乐观锁、`@Filter`/`@TenantId` 行级范围、软删除、审计；库存/POS/促销热路径保留 JdbcTemplate，但复用同一 scope 与审计组件。

### 2.2 行级数据范围（硬性）

**CR-010（MUST）** 所有外部数据访问必须有行级范围：

- 供应商只看自己；
- 门店只看 `staff_store` 绑定门店；
- 客服只看分配会话/组；
- 运营按权限；
- 导出遵守相同范围。

**CR-011（MUST）** 行级范围通过统一 `ScopeResolver` / JPA `Specification` / Hibernate Filter 实现；禁止在每个 Controller 手写 where 条件。越权返回 404/403，并有负向测试。

**CR-012（MUST）** 供应商不得通过“继承实体”获得写权限；供应商的读写范围由行级 scope + DTO/策略决定。成本、毛利、内部备注、风控标记、其他供应商数据默认不返回，任何越权写字段返回 400/403，不得静默丢弃。

### 2.3 字段可见性（非硬性，按需）

**CR-020（SHOULD）** 默认用 DTO/投影裁剪输出字段；`@JsonView` 只能做序列化裁剪，不能代替输入校验或安全。

**CR-021（MAY）** 仅当 ERP 明确需要（成本、毛利、薪资、供应商底价等）时启用字段级可见性。必须使用成熟策略引擎：

- OPA（CNCF，Rego，决策 API）；或
- Casbin/jCasbin（嵌入式 ABAC）；
- 由策略返回允许字段/脱敏值，应用用 DTO 执行；
- **不自建“每张表字段-角色”权限矩阵/后台**。

**CR-022（MUST）** Spring Security 只提供请求/方法/对象级授权，不原生支持字段级；Keycloak Authorization Services 也不提供自动字段脱敏。不得把它们宣称为字段级方案。

**CR-023（SHOULD）** ERP 角色可见性参考 Odoo `groups=`/record rules、ERPNext permlevel 的产品模型；只借鉴，不复制代码。

### 2.4 基础控制器与服务

**CR-030（SHOULD）** 通用 CRUD 可用基础控制器/服务封装分页、校验、审计、幂等、乐观锁；但权限判断必须委托 Spring Security + `ScopeResolver`，不自建字段权限钩子。

**CR-031（MUST）** Admin、供应商、门店、客服可以复用基础 CRUD，但专有动作（接单/发货/审批）必须在子类实现；禁止复制粘贴 CRUD。

**CR-032（MUST）** 禁止把实体直接序列化给外部；必须使用 DTO/投影。供应商 DTO 不得包含内部字段。

**CR-033（MUST）** 批量更新/导入必须走同一 scope 与校验；导入接口不得绕过权限。

### 2.5 研究门槛

**CR-040（MUST）** 每个新需求/模块在实现前必须完成技术选型调研，记录候选、许可证、维护活跃度、安全、集成方式、放弃理由；没有记录的“自研”不得进入开发。

**CR-041（MUST）** 优先采用成熟方案：Spring Security、Spring Data JPA/Hibernate、MapStruct、JaVers、Flowable、Drools/Easy Rules、Unleash/FF4j、Spring AI/LangChain4j、Tolgee/Weblate、springdoc/OpenAPI Generator、Resilience4j、Bucket4j、Apache Tika/ClamAV、官方支付/云存储 SDK。详见 `TECHNOLOGY_DECISIONS_V2.md`。

## 3. 供应商协同

### 3.1 交互模式

**SUP-001（MUST）** 模式 A：请求/响应。供应商通过平台 Web 门户或自建客户端调用 `/open/v1`，平台等待请求并返回结果。

**SUP-002（MUST）** 模式 B：平台主动通知。缺货、待发货、订单变更、结算、退货等事件由平台推送；供应商可拉取 + WSS 持续接收。

**SUP-003（MUST）** 供应商待办中心必须同时支持：

- 首次进入/断线重连全量拉取；
- WSS 增量推送；
- 消息序号/确认/断线补拉；
- 未读数、已办、超时提醒；
- 与订单/库存/结算/退货详情深链。

**SUP-004（MUST）** WSS 不可用时降级为轮询，但必须显示连接状态；生产环境不得假装实时。

### 3.2 供应商门户

**SUP-010（MUST）** 供应商门户只调用对外供应商 API，不另建一套“内部供应商 API”。

**SUP-011（MUST）** 门户登录后通过 BFF/会话换取短期 API 凭证，业务请求仍走 `/open/v1`；禁止前端持有长期 secret。

**SUP-012（MUST）** 门户功能：待办、订单接单/发货/拒单、库存 feed、结算单、退货协同、Webhook 配置、API 文档/密钥轮换。

**SUP-013（MUST）** 供应商关闭开关生效后：`/open/v1` 返回明确 403/503，供应商 Web 不能登录，已登录会话失效；后台仍可查看历史数据。

### 3.3 结算、CSV、Webhook、退货

**SUP-020（MUST）** 结算单：按周期生成，包含订单、扣款、佣金/服务费、退货冲减、应付金额、币种、状态（草稿/确认/已支付/争议）。

**SUP-021（MUST）** CSV：订单/结算/退货模板导入导出；上传必须校验表头、类型、金额、重复键、业务键；错误行返回行号与原因，不允许部分成功静默。

**SUP-022（MUST）** Webhook：

- 事件订阅（订单、库存、结算、退货）；
- HMAC 签名 + 时间戳 + nonce；
- 至少一次投递 + 指数退避重试；
- 投递记录、响应码、耗时、失败原因；
- 手动重放；
- 死信队列与告警；
- 供应商可配置回调 URL 白名单。

**SUP-023（MUST）** 退货对账：退货申请、收货、质检结果、补发/退款/报损、供应商责任判定、结算冲减；支持按月对账和差异处理。

**SUP-024（MUST）** 供应商侧不要求采购审批和复杂质检；自营 ERP 的采购/质检见 7.2。

### 3.4 供应商 API 安全

**SUP-030（MUST）** 认证支持两种方式，至少启用一种：

- Bearer Token/API Key（可轮换、可吊销、可设过期）；
- IP allowlist（CIDR，支持多段）。

**SUP-031（MUST）** 生产环境建议二者同时启用；只配置一种时必须在后台显示风险提示。

**SUP-032（MUST）** 服务端到服务端写操作使用 HMAC-SHA256：method + path/query + timestamp + nonce + body hash；时间窗 ±300s；nonce 防重放；常量时间比较。

**SUP-033（MUST）** 限流：按供应商/接口/时间窗；超限返回 429 + `Retry-After`；关键写接口有幂等键。

**SUP-034（MUST）** 风险预警：异常 IP、连续 401/403、nonce 重放、签名失败、批量拉取、异常时间、Webhook 连续失败、结算差异超阈值；产生站内/邮件告警和审计记录。

## 4. 客服系统

### 4.1 分组、技能与路由

**CS-001（MUST）** 客服分组/分类：售前、售后、语言（es/ru/其他）、技能、渠道、班次。

**CS-002（MUST）** 会话按规则路由：语言、业务类型、订单状态、客户等级、历史客服、当前在线负载。

**CS-003（MUST）** 已分配客服离线时自动转单给同组在线客服；无在线同组时转机器人/排队；转单记录原因、前后客服、时间。

**CS-004（MUST）** 主管可查看跨组会话、队列、SLA、质检；普通客服只能看自己/本组分配。

### 4.2 实时通信

**CS-010（MUST）** 用真实 WebSocket 替换 echo stub：鉴权 ticket、会话订阅、seq/ack、断线补拉、心跳、重连。

**CS-011（MUST）** 消息类型：文本、图片、文件、商品卡片、订单卡片、物流卡片、帮助链接、系统消息。

**CS-012（MUST）** 已读回执、正在输入、会话关闭/重开、转单、静默、拉黑、满意度评价。

**CS-013（MUST）** 附件上传：类型/大小/病毒扫描/MIME 校验/签名 URL；演示模式限制。

**CS-014（MUST）** 顾客侧聊天入口：商城悬浮入口、移动端适配、未读提醒、离线留言、断线补拉。

### 4.3 AI 与知识库

**CS-020（MUST）** `BotEngine` SPI；演示模式使用 Mock Bot（固定 FAQ/订单查询）；生产模式未配置 AI 服务商时**明确报错**，不得静默返回空答案。

**CS-021（MUST）** 知识库/RAG：文档导入、分块、向量检索、引用来源、按市场/语言/权限隔离、版本与下线。

**CS-022（MUST）** AI 工具：订单查询、物流查询、退款资格、门店库存、自提状态；工具调用必须鉴权与审计。

**CS-023（MUST）** 安全：Prompt Injection 防护、PII 脱敏、输出审核、人工接管、限流/成本上限、评测集与灰度。

**CS-024（MUST）** SLA/质检：首响、解决时长、超时升级、会话抽检、评分、违规词、AI 摘要。

## 5. 线上会员与促销

### 5.1 线上会员

**MEM-001（MUST）** 线上会员登录：手机号 OTP 为主，后续可接微信/支付宝；会员与 POS 会员同一 `member` 主体。

**MEM-002（MUST）** 线上结算按会员等级计算折扣、积分倍率、成长值、生日礼；匿名结算不享受会员权益。

**MEM-003（MUST）** 成长值/积分/生日礼以账本记录；退款按比例回滚；生日礼每年一次，规则后台可配。

**MEM-004（MUST）** 会员价/等级价与促销叠加规则由促销引擎统一计算，不允许前端算价。

### 5.2 促销引擎

**PRO-001（MUST）** 支持：满减、满折、满赠、买赠、秒杀、拼团、优惠券、会员折扣、砍价。

**PRO-002（MUST）** 规则引擎支持条件-动作、优先级、时间窗、渠道、市场、商品/类目/品牌范围、会员等级、每人/每单限购。

**PRO-003（MUST）** 叠加/互斥策略可配置；必须能计算“最优价”并展示优惠明细；冲突规则有明确优先级。

**PRO-004（MUST）** 渠道隔离：线上（PC/H5/APP/小程序）与门店 POS 使用独立活动集合；同一活动不可默认跨渠道生效。

**PRO-005（MUST）** 门店自提只做提货核销，不再计算线上优惠；线上订单已支付/已优惠，POS 自提不得二次打折。

**PRO-006（MUST）** POS 卖货可使用门店专属促销/会员/优惠券；与线上促销分开配置、分开审计。

**PRO-007（MUST）** 秒杀/拼团/砍价的名额、限购、活动库存必须服务端原子校验；售罄明确报错。

**PRO-008（MUST）** 促销试算 API：输入商品、数量、会员、渠道、时间，返回命中规则、优惠明细、应付；后台可预览。

**PRO-009（MUST）** 未支付订单超时取消时释放促销名额；退款/取消按规则回滚；拼团失败自动退款（生产适配器可用时）。

## 6. 支付与对账

**PAY-001（MUST）** 适配器：微信支付、支付宝、银联、聚合收单；统一 `PaymentConnector` SPI（create/confirm/capture/refund/query/webhook/reconcile）。

**PAY-002（MUST）** 后台配置真实凭证：商户号、AppID、API v3 key、证书、私钥、回调地址、平台公钥；敏感字段加密存储、掩码显示、轮换审计。

**PAY-003（MUST）** 演示模式使用 Mock；生产模式缺少凭证时启动失败/支付接口明确报错，禁止回退 Mock。

**PAY-004（MUST）** Webhook 验签、幂等 inbox、重复/乱序处理、退款/部分退款、异常告警。

**PAY-005（MUST）** 对账文件导入：渠道流水 vs 订单 vs 退款 vs 结算；差异分类、人工处理、日结报表。

**PAY-006（MUST）** 拼团失败退款在生产环境使用真实适配器；适配器不可用时明确失败并告警，不得标记退款成功。

## 7. 自营 ERP、售后与门店

### 7.1 售后

**ERP-001（MUST）** 换货补发：申请、审核、收货、质检、补发订单/履约单、库存扣减/预占、物流回传。

**ERP-002（MUST）** 质检报损：不合格品进入隔离/报损批次，生成报损单、成本影响、供应商责任/结算冲减。

**ERP-003（MUST）** 退货对账：退款、补发、报损、供应商赔付/冲减可追溯。

### 7.2 自营采购与仓储

**ERP-010（MUST）** 采购单：供应商、商品、数量、价格、交期、仓库；**不做多级采购审批**。

**ERP-011（MUST）** 到货预约：时间段、月台/仓库容量、供应商确认、改约/取消、超时。

**ERP-012（MUST）** 质检上架：收货 → 质检（合格/不合格/让步接收）→ 上架批次 → 库存可用；不合格转隔离/退货/报损。

**ERP-013（MUST）** 盘点审批：盘点单提交、差异复核、审批、库存调整流水；报损单：原因、批次、数量、成本、审批、审计。

**ERP-014（SHOULD）** 自营 ERP 具备正常 ERP/OA/Admin 能力：采购、收货、质检、上架、调拨、盘点、报损、供应商对账、操作审计；但不做复杂 MRP/多级审批。

**ERP-015（MUST）** 供应商侧保持轻量：订单/库存/发货/结算/退货协同，不要求供应商使用采购审批/质检模块。

### 7.3 门店授权

**STORE-001（MUST）** 店长改价授权：收银员发起，店长 PIN/账号审批，记录原价/新价/原因/授权人。

**STORE-002（MUST）** 作废授权：整单/行作废需店长授权；记录原因、库存回补、支付冲正。

**STORE-003（MUST）** 交接班审核：交班现金、差异、未结事项、店长确认；审计留痕。

**STORE-004（MUST）** 员工排班：班次、门店、岗位、请假/调班；与收银开班关联。

**STORE-005（MUST）** 线下扫码/支付宝碰一碰：演示模式 Mock；生产模式缺少终端/商户配置时明确报错，不得假装成功。

## 8. 多语言、多币种与素材库

### 8.1 多语言/RTL

**I18N-001（MUST）** 支持 en/es/fr/ar 与 RTL；默认 zh-CN，回退链明确。

**I18N-002（MUST）** 使用成熟开源方案：Vue I18n/Nuxt I18n、ICU MessageFormat、CSS logical properties、`dir=rtl`、镜像布局；不自行实现 RTL 引擎。

**I18N-003（MUST）** 翻译流程：AI 自动翻译 + 人工校对/修正；保存翻译记忆、术语表、审校状态、版本。

**I18N-004（MUST）** 法律文档、支付/隐私相关文案必须人工审校；AI 结果不得直接上线。

**I18N-005（MUST）** 多币种：CNY/HKD/MOP/TWD；价格表按市场/币种；汇率快照与舍入规则；前台按当地币种显示。

**I18N-006（MUST）** 港澳台支付/物流可先实现适配器代码；演示 Mock；生产缺少 AK/token 时明确报错。

### 8.2 素材库

**AST-001（MUST）** Admin 素材库分公共库/个人库；支持文件夹、标签、搜索、上传、预览、替换、引用统计。

**AST-002（MUST）** 素材删除默认软删除；被引用素材禁止直接物理删除；提供恢复、彻底删除（仅管理员）和引用检查。

**AST-003（MUST）** 存储抽象：本地、SeaweedFS/S3、七牛、阿里云 OSS；签名 URL/CDN；后台切换服务商。

**AST-004（MUST）** 切换云存储时旧资源必须可继续访问：迁移任务、双读、校验、切换、回滚；素材元数据与文件分离，禁止断链。

**AST-005（MUST）** 上传安全：类型/大小/MIME/病毒扫描/图片重编码；防盗链、限流、审计。

**AST-006（SHOULD）** 视频转码/封面/多清晰度可后续接入成熟服务。

## 9. 功能开关

**FLAG-001（MUST）** 后台可开关供应商模块：关闭后 `/open/v1`、供应商 Web、登录、Webhook 全部不可用；后台历史数据仍可查。

**FLAG-002（MUST）** 收银台拆分为两个开关：`pos.sale`（卖货）与 `pos.pickup`（自提核销）。可单独关闭。

**FLAG-003（MUST）** 站点开关：`OPEN / MAINTENANCE / CLOSED`。关闭时前台客户功能不可用，仅 Admin 可用；支付回调、退款回调、健康检查、内部任务不受影响。

**FLAG-004（MUST）** 开关变更实时生效（缓存 TTL ≤ 30s），审计记录操作人/时间/原因；前端显示明确提示。

**FLAG-005（MUST）** 开关不得通过前端隐藏实现安全；服务端必须强制。

## 10. 数据权限、审计与风控

**SEC-001（MUST）** 行级：供应商自身、门店绑定、客服分配/组、运营权限；字段级：成本/毛利/密钥/内部备注/个人信息。

**SEC-002（MUST）** 导出脱敏：按角色/字段/范围；导出任务审计、限流、水印/文件过期。

**SEC-003（MUST）** 操作日志覆盖：登录、权限变更、价格/库存/订单/退款/结算/开关/密钥/导出/供应商 API 写操作。

**SEC-004（MUST）** 风险预警：异常登录、越权、签名失败、批量导出、结算差异、Webhook 失败、支付差异、库存异常。

**SEC-005（MUST）** 审计日志不可篡改（追加写），保留周期可配置；PII 脱敏。

## 11. API 版本与对接文档

**API-001（MUST）** 供应商 API 版本化：`/open/v1`、`/open/v2`；同一版本内向后兼容。

**API-002（MUST）** 每个版本提供：OpenAPI、字段说明、错误码、签名示例、CSV 模板、Webhook 事件、变更日志、弃用时间表。

**API-003（MUST）** 文档自动生成/校验：从代码/OpenAPI 生成，CI 检查与实现不一致；版本发布自动更新文档站点。

**API-004（MUST）** 弃用策略：Deprecation/Sunset header、至少一个版本周期、迁移指南、双版本并行。

**API-005（MUST）** 沙箱/演示环境：Mock 数据、固定测试凭证、可重放 Webhook；生产凭证隔离。

## 12. 非功能需求

- **NFR-001 安全**：OWASP ASVS；认证/授权/输入校验/限流/加密/密钥管理/依赖扫描。
- **NFR-002 性能**：下单/库存/POS/支付 P95 目标；压测与容量计划。
- **NFR-003 可用性**：支付回调/库存/订单关键路径幂等、重试、补偿；备份恢复演练。
- **NFR-004 可观测**：trace/order/fulfillment/store/supplier/conversation ID；指标、日志、告警。
- **NFR-005 兼容**：演示模式可完整走通；生产缺少配置必须 fail-fast。
- **NFR-006 可维护**：模型单一定义、基础控制器复用、模块边界、契约测试。
- **NFR-007 合规**：PIPL/PDPO/PDPA/台湾地区个资法；法律文本人工审校；数据出境评估。

## 13. 验收总则

- 每个 MUST 需求至少有一个自动化测试或可复现验收脚本。
- 安全相关需求必须有越权/未授权/重放/限流测试。
- 演示模式全流程可走通；生产模式缺配置有明确错误。
- 数据权限必须有“同角色越权被拒绝”的负向测试。
- 文档与代码版本一致；供应商 API 变更必须有 changelog。
- 所有金额、库存、结算、退款必须有对账或一致性校验。
