# ADR-0007: Demo / Prod 双构建模式

- 状态：Accepted
- 日期：2026-10-18

## 背景

开源版本需要提供可走通的全套演示流程，但公开演示站不能允许真实写入、真实支付或外部消息发送，否则会被滥用。客户需要自行配置支付并编译正式站。

## 决策

- 通过 Maven/Spring profile、前端环境变量和 Docker build args 区分 `demo` 与 `prod`。
- `demo` 模式：
  - 默认启用 Mock 支付、物流、短信、邮件、地图、发票。
  - 公开演示站仅允许 GET 和 `/mock/**` 的 GET 请求；禁止 POST/PUT/DELETE。
  - 只读数据库用户；无外网 egress；禁用上传和真实客服发消息。
  - noindex、限流、演示横幅、定时重置、无 PII。
- `prod` 模式：
  - 真实适配器必须显式配置；缺失配置启动失败（fail-fast）。
  - 密钥通过环境变量/密钥管理注入，不入库、不入 Git。
- 客户可配置 `.env` 和适配器后执行 `make build-prod`，无需修改核心代码。
- 公开演示站与可交互 sandbox 分开部署；sandbox 使用临时数据，不对外承诺。

## 后果

- 需要两条 CI 构建和演示站专项测试（POST 必须返回 405）。
- Mock 适配器必须与真实适配器实现同一 SPI，避免演示逻辑分叉。
- 演示数据必须可重复生成。

## 替代方案

- 演示站允许真实写入：不可接受，存在滥用和数据污染风险。
