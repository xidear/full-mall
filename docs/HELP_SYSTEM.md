# 后台帮助体系（怎么保证不落后于代码）

## 1. 三层内容

| 层 | 位置 | 作用 |
|---|---|---|
| 页面内提示 | 各页面的 `el-alert` / 表单 `placeholder` / 表格 `empty-text` | 操作当下就能看到，不用跳走 |
| 页面帮助抽屉 | `web/apps/admin/src/help/catalog.ts` → 顶栏「帮助」按钮 | 该页的步骤/运营建议/常见错误 |
| 索引文档 | `docs/HELP_INDEX.md`（脚本生成） | 交付/培训用，可打印 |

## 2. 每条帮助必须有的字段

```ts
{
  route: '/orders',          // 必须与 router.ts 完全一致
  title: '订单管理',
  description: '这个页面解决什么问题',
  steps: ['操作顺序'],        // 非空
  tips: ['运营建议'],         // 非空，写"为什么"而不只是"怎么做"
  pitfalls: ['常见错误与后果'], // 非空
  related: ['/after-sales']   // 可选，必须是真实路由
}
```

## 3. 自动防落后的机制（这是重点）

`scripts/check-help-coverage.py` 在验证流程第 5 步执行，任一情况**直接失败**：

| 检查 | 触发场景 |
|---|---|
| 路由 → 帮助缺失 | 新增页面但没写帮助 |
| 帮助 → 路由不存在 | 删页面后留下死链 |
| 必填字段为空 | `steps` / `tips` / `pitfalls` 空数组 |
| `related` 指向不存在页面 | 帮助里写了错的跳转 |
| `docs/HELP_INDEX.md` 与内容不一致 | 改了帮助但没重新生成索引 |

重新生成索引：

```bash
python3 scripts/check-help-coverage.py --write
```

已实测反证：手动改坏 `HELP_INDEX.md` → 脚本退出码 1 并指出"与帮助内容不一致"；恢复后退出码 0。

## 4. 为什么不放在后端接口里

帮助是**静态内容**，随前端版本发布；放后端会导致"后端没升级但前端已引用"的错位。
现在帮助与路由在同一个 TypeScript 模块里编译，**版本天然一致**。

## 5. 已知限制

- 字段级提示（每个输入框的 tooltip）尚未全量覆盖，目前覆盖页面级与关键操作；
- 帮助内容只覆盖后台，门店收银/供应商/客服前端待补；
- 文案目前中文单语，多语言需要把 catalog 换成 i18n key。
