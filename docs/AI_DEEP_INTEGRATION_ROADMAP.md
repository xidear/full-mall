# AI 深度参与演进路线（ADR-002）

> 现状：**权宜方案** —— 商品数据被索引成知识块，检索后拼给第三方模型作答。
> 目标：自部署模型、AI 深度参与业务，甚至能查库。

## 阶段划分（每阶段都可独立交付、可回退）

### 阶段 0（当前）：索引 + 外调模型

| 项 | 状态 |
|---|---|
| 数据 | 商品/文档 → `knowledge_chunk`（关键词 + 可选向量） |
| 模型 | OpenAI 兼容外部 API |
| 能力 | 只读问答，带引用与约束 |
| 局限 | 数据出内网；只能答"资料里有的"；不能查实时状态（如"我的订单到哪了"） |

### 阶段 1：模型自部署（数据不出内网）

- 推理：`.15`（5070Ti）跑 7B~14B 量化；`.8`（2×V100）跑更大模型；
- 代码改动：**零**（同一 OpenAI 兼容接口，只改 `app.ai.chat-base-url`）；
- 验收：同一批 50 条问题的答案质量不低于外部模型 90%；P95 首字延迟 < 2s。

### 阶段 2：工具调用（AI 受控"查库"）——**推荐的深水区入口**

模型不再只读资料，而是可以**调用我们实现的只读工具**：

```json
{"tool":"order.status","args":{"orderNo":"SO202610190001","phoneLast4":"1234"}}
→ 返回 {"status":"已发货","carrier":"顺丰","trackingNo":"SF123...","lastEvent":"已签收"}
```

| 要求 | 说明 |
|---|---|
| **不是 SQL** | 工具是服务端实现的有类型函数，参数校验、权限、限流都在服务端 |
| 只读优先 | 阶段 2 只允许查询（订单/物流/库存/价格/券资格） |
| 身份约束 | 顾客会话只能查**自己的**订单（按会员 id 或手机号+尾号校验） |
| 审计 | 每次调用写 `ai_tool_call`（谁、什么参数、返回摘要、耗时），可回溯 |
| 脱敏 | 手机号/地址按掩码返回，模型拿不到完整 PII |
| 失败即拒 | 工具报错就把错误交给模型并转人工，不静默降级 |

代码落点（新增企业版模块内）：

```
ai/tool/AiTool.java            接口：name/schema/execute(Actor, args)
ai/tool/ToolRegistry.java      注册表 + 权限声明
ai/tool/ReadOnlyTools.java     订单/物流/价格/库存/券资格
ai/tool/ai_tool_call 表        V77 审计
```

### 阶段 3：受控写操作（人审后执行）

- AI 只能**生成草稿**（补发申请、优惠券补偿、售后单），由客服一键确认后执行；
- 金额类动作（退款/改价/免单）**永远需要人工点击**，AI 只有建议权；
- 验收：所有写操作都有 `requestedBy=ai` + `approvedBy=人工` 的双签记录。

### 阶段 4（可选，高风险）：自然语言直接查库（Text-to-SQL）

只有在阶段 2 被证明不够用时才考虑，且必须满足：

| 护栏 | 具体要求 |
|---|---|
| 只读副本 | 连接只读账号，数据库层面禁止写 |
| 视图白名单 | 只暴露脱敏视图（无手机号明文、无支付凭证） |
| 语句限制 | 仅 SELECT；禁止子查询嵌套深度 > 3；强制 LIMIT ≤ 500 |
| 超时与成本 | 语句 3s 超时；每会话查询次数上限 |
| 审计与告警 | 全量 SQL 入库；出现非白名单表访问立即告警并禁用 |
| 双人复核 | 新增视图/放开表需要两人审批 |

**我的判断**：阶段 2 的工具化能覆盖 90% 的"查库"需求，且风险可控；
Text-to-SQL 的收益主要是"运营自助分析"，应该做成**报表/智能问数**产品，而不是塞进客服对话。

## 关键风险与对策

| 风险 | 对策 |
|---|---|
| 模型幻觉 + 查库结果混在一起 | 工具返回结构化数据 + 回答必须引用工具结果；金额以工具返回为准，不接受模型改写 |
| 顾客越权查他人订单 | 工具入参必须绑定当前会话身份，禁止仅凭订单号查询 |
| 数据外泄 | 阶段 1 起模型自部署；阶段 2 工具只返回必要字段 |
| 模型被诱导执行危险动作 | 阶段 2/3 动作白名单 + 人工确认；不在 prompt 里给"权限"，权限在服务端 |
| 依赖外部 API 涨价/停服 | 阶段 1 已完成自部署即可切换，代码零改动 |

## 里程碑与验收

| 阶段 | 验收标准 |
|---|---|
| 1 | 自部署模型回答质量 ≥ 外部模型 90%；数据不出内网 |
| 2 | 5 个只读工具上线；越权查询 100% 被拒（有测试）；调用审计可查 |
| 3 | 写操作 100% 双签；无 AI 直接执行的资金动作 |
| 4 | 仅当 2 不满足需求时启动；护栏缺一不可 |

## 现在要做的准备（不改现有行为）

1. 知识块保留稳定 `source_id`（已具备）——将来工具与检索可共用；
2. 会话身份信息（会员 id / 客服 id）传入 AI 层——阶段 2 权限判断依赖它；
3. 评测集（50 条问题 + 期望答案）——阶段 1 切换模型时对比用；
4. `ai_tool_call` 表结构先设计好（V77 待建）。
