# 促销与优惠券引擎规格（用户口径 2026-10-19）

> 背景：我此前问"STACK 是否与券同栈"表述含糊。真实模型是：**每个活动/券都带一组开关**，
> 能不能叠加由这些开关决定，而不是全局一个模式。

## 1. 活动的属性（营销活动侧）

| 属性 | 取值 | 说明 |
|---|---|---|
| 类型 | 满减 / 满折 / 秒杀 / 买赠 / 拼团 | 已有 |
| 门槛基准 | `BEFORE_DISCOUNT`（按原价判断）/ `AFTER_DISCOUNT` | **需新增可配**：满 200 是"促销前"还是"促销后" |
| 允许叠加优惠券 | 是 / 否（默认否） | 参与活动的商品能否再用券 |
| 允许积分抵扣 | 是 / 否（默认否） | 活动商品是否允许积分抵现 |
| 允许叠加其它活动 | 是 / 否 + 互斥组 | 同组互斥（如两个满减不能叠加） |
| 参与范围 | 全部 / 类目 / 指定商品 | 已有 `scope` |
| 排除 | 指定商品 / 指定类目 | **需新增**：类目参加但排除个别商品 |
| 时间窗 | 起止时间 | 已有 |

## 2. 优惠券的属性（券模板侧）

| 属性 | 取值 | 说明 |
|---|---|---|
| 面额与门槛 | 满 X 减 Y | 已有 |
| 可叠加 | 是 / 否（默认否） | **用户可手动多选**的前提 |
| 适用范围 | 全部 / 类目 / 商品 / 品牌 | 已有 `scope` |
| 排除 | 指定商品/类目 | 需新增 |
| 有效期 | 固定窗口 / 领取后 N 天 | 已有 |
| 渠道 | 线上 / 门店 / 通用 | 已有 `channel` |
| 每人限领、总量 | — | 已有 |

## 3. 结算流程（用户明确）

1. **默认不选券**，但界面必须提示"有可用券，使用后可省 X 元"（不能默认替顾客选，除非他点了）；
2. 系统给出**推荐最优单个券**；
3. 若券 `stackable=true`，顾客可**手动勾选多个**；不满足互斥/门槛的组合要即时提示原因；
4. 积分抵扣按活动/券的开关判断，不允许时明确提示"该商品不支持积分抵扣"；
5. 门槛判断按活动的 `门槛基准` 配置执行，**同一单里不同活动可以不同基准**（各自判断）。

## 4. 数据模型改动（相对现状）

| 表 | 现状 | 需补 |
|---|---|---|
| `promotion.rules`（JSONB） | skuId/价格/库存/限购等 | `allowCouponStack`、`allowPoints`、`thresholdBasis`、`excludeSkuIds`、`exclusiveGroup` |
| `coupon_template` | 面额/门槛/范围/有效期/渠道 | `stackable` 已在用；补 `excludeSkuIds`、`stackGroup` |
| 结算 | 券 `EXCLUSIVE/STACKABLE` 全局开关 | 改为**逐券属性 + 活动属性**联合判断 |

## 5. 判定伪代码（结算）

```
eligible = 活动候选(时间/范围/排除/门槛基准)
appliedPromotions = 按互斥组与优先级选择（活动自身规则）
couponEligible = 顾客券 ∩ 适用范围(排除) ∩ 未过期 ∩ 门槛(按应用后金额或原价，按券配置)
if 某活动.allowCouponStack == false 且该活动已应用:
    couponEligible 需排除该活动覆盖的商品
pointsAllowed = 所有已应用活动/券的 allowPoints 都为 true
最终：默认推荐 1 张最优券；若 stackable，可多选；实时显示"已省/可再省"
```

## 6. 与现有实现的差距

| 现有 | 状态 |
|---|---|
| 活动范围（全部/类目/商品）、时间窗、限购、售罄、活动价覆盖 | ✅ 已实现 |
| 券面额/门槛/范围/有效期/限领/总量/渠道 | ✅ 已实现 |
| 券 `stackable`（EXCLUSIVE/STACKABLE） | ⚠️ 全局模式，未按券属性 |
| 活动"允许叠加券/积分" | ❌ 无 |
| 门槛基准可配 | ❌ 无（当前固定按促销后金额判断，需确认） |
| 活动/券的排除项 | ❌ 无 |
| 结算推荐最优 + 手动多选 | ❌ 无（当前单选/自动） |

## 7. 实施顺序（每步可独立验收）

1. **数据**：活动 rules 与券模板补属性（迁移），后台表单暴露开关；
2. **判定引擎**：`PromotionEngine` 支持 `thresholdBasis`、`allowCouponStack`、`allowPoints`、排除项，纯函数 + 单测；
3. **结算接入**：默认推荐最优券 + 不默认勾选；按属性允许手动多选；
4. **前端**：券选择区显示"可用 N 张、最优省 X"，勾选/取消即时重算；
5. **E2E**：满减后门槛判断、叠加被拒提示、积分不可用提示。

## 8. 需要你确认的两个默认值

| 问题 | 建议默认 |
|---|---|
| 门槛基准默认 | `AFTER_DISCOUNT`（按促销后金额算满减门槛，避免"看起来够但实际不够"） |
| 多张券可叠加时优惠上限 | 由券自身面额决定，不设全局百分比上限（否则规则难以解释） |
