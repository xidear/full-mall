# ADR-0008: 企业版与更新边界

- 状态：Accepted
- 日期：2026-10-18

## 背景

项目计划提供开源核心和企业版，并预留企业级版本更新能力。需要避免企业功能污染开源核心，也要保证自托管客户可以安全升级。

## 决策

- 源码开放核心使用 PolyForm-Noncommercial-1.0.0（仅限非商业用途，2026-10-18 由 Apache-2.0 调整）；企业模块独立仓库/镜像，通过稳定 SPI 或独立服务集成，商业使用需另行授权。
- `edition` 支持 `community` / `enterprise`；企业版使用签名 license 文件和 `entitlement` 控制功能。
- 核心交易流程不得依赖企业模块；企业模块缺失时核心仍可运行。
- 更新机制：
  - 签名 release manifest（版本、校验和、迁移、兼容性）。
  - 在线/离线更新包；预检、备份、维护模式、迁移、健康检查、回滚。
  - 管理端提供更新页面和审计日志。
  - Docker/Helm 部署支持镜像版本固定和回滚。
- v1 只实现接口和骨架，不实现自动更新服务。

## 后果

- 需要维护插件 API 版本兼容和数据库迁移兼容。
- 企业功能边界必须在产品层面明确，避免“开源版残废”。
- 更新流程必须可离线，适配私有化部署。

## 替代方案

- 直接闭源企业分支：维护成本高，社区贡献难合并。
