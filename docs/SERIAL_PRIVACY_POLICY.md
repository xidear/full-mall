# 序列号（IMEI）查询的隐私边界

## 原则

1. **不对顾客提供**：任何人问"某 IMEI 现在在哪、卖给了谁"，一律回复
   "请通过品牌官方售后渠道核实"，不查询、不透露、不解释内部流程。
2. **不对供应商提供**：供应商只能看到自己订单的发货状态，**不含序列号与最终顾客信息**。
3. **内部仅 ADMIN 可用**：接口 `GET /admin/v1/serials/{no}` 需 `ROLE_ADMIN`；
   运营/客服角色**无权**调用（如需协助，由管理员代办并留痕）。
4. **每次查询必须留痕**：写审计事件 `SERIAL_LOOKUP`（操作人、序列号、时间）。
5. **最小化返回**：只返回批次、SKU 编码、状态、订单行 ID；
   **不返回**顾客姓名、手机号、地址——内部排查也不需要这些。

## 为什么这么严

- IMEI 是设备唯一标识，能关联到具体买家 → 属于个人信息；
- "查设备位置/归属"这类请求，本质是售后鉴定，属于**品牌方职责**，不是渠道商的义务；
- 一旦对外开口子，会被用于"验机""查二手来源""骚扰买家"，法律与声誉风险都高。

## 客服话术（统一）

> "设备相关的真伪与保修信息，请通过品牌官方售后或授权服务中心核实。
> 我们无法查询或提供设备的归属与流转信息。"

## 允许的内部场景（仍需 ADMIN + 留痕）

| 场景 | 说明 |
|---|---|
| 仓库盘点差异排查 | 确认某序列号是否在本仓、是否已出库 |
| 售后纠纷取证 | 确认该设备是否由本店售出（仅返回订单行，不看顾客信息） |
| 供应商退换货核对 | 确认退回设备是否原批原货 |
