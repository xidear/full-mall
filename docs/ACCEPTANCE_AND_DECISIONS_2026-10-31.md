## 二、反问清单（如果当时问你，我会这么问）

### Q1. 15052 应该跑「开发服务器」还是「生产构建」？

- **A. Vite dev（现状）**：改代码即热更新，排查方便；但 15052 是给运营用的入口，dev 服务器会暴露源码、
  依赖浏览器实时编译，且没有构建期类型检查。**不选**。
- **B. `vite preview` 提供 `dist`（已选）**：与生产同源代理，仍由 41281 提供；构建期跑 `vue-tsc`，
  资源改用 `/ui/**` 避开 API 的 `/assets/**`。取舍：改代码后必须重新 build（已写进文档）。
- **C. nginx 静态托管 + 反代**：最接近生产，但需要改运维 compose/证书，超出本批范围。

**选择 B 的原因**：15052 是运营入口，必须先保证“看到的是构建产物”；同时不引入新的 nginx 配置面，
风险最小。B 的缺点（需重新构建）已写进 `ACCEPTANCE_MANUAL` ⑪。

### Q2. 真实模型用「本机 9B」还是「免费云端」？

- **A. 本机 Ollama + qwen 9B**：数据不出内网；但本机无 GPU，CPU 推理 9B 约个位数 token/s，
  客服并发直接不可用，还要 5–10GB 磁盘与模型运维。**不选**（保留为可选供应商）。
- **B. 公司自营 OpenAI 兼容端点 `deepseek-v4.1-flash`（已选）**：本机网络内、无需 Key、实测 200、
  与现有 `openai-chat` 适配器零改造；代价是依赖该端点可用性（不可用→503，不影响下单）。
- **C. OpenRouter / OpenCode 等免费模型**：免费但需账号/Key，配额与可用性随活动变化，数据出境。

**选择 B 的原因**：在“真实、可复现、免费、无需 GPU”四个条件里，B 同时满足；
A 在本机跑不动 9B，C 引入外部账号与合规不确定性。供应商可在后台随时切换（页面已提供）。

### Q3. 检索用「语义」还是「关键词」？

- **A. 只用 SEMANTIC**：召回质量最好；但本机没有 embedding 服务，整条问答链 503。**不选**。
- **B. 只用 KEYWORD（已选默认）**：FAQ/短问答可用，零外部依赖；文档型长知识召回弱。
- **C. 失败自动降级 KEYWORD**：看似稳妥，实际让运营误以为语义检索在工作，违反“禁止静默兜底”。**禁止**。

**选择 B + 显式开关的原因**：在 `app.ai.ask.retrieval` 明确选择，并在 AI 状态页展示；
以后配好 embedding 改一行配置即可切 SEMANTIC，不需要改代码。

### Q4. 门店“停用”还是“删除”？

- **A. 物理删除**：列表干净；但订单、库存批次、POS 班次都引用门店，删除会留下悬空引用。**不选**。
- **B. `active` 启停（已选）**：可逆、保留历史；代价是列表需要「全部状态」筛选。

**选择 B 的原因**：门店是交易事实的一部分，不是可丢弃的配置；停用已能满足“不再可选”的业务目标。

### Q5. 进行中的促销能不能直接编辑？

- **A. 允许直接改**：运营改价最快；但用户看到的价与结算价会在眼皮下变化，出问题无法归因。**不选**。
- **B. 只允许改草稿 + 复制为草稿（已选）**：改活动先结束旧活动、改副本再启用；多一步操作，换来可追溯。
- **C. 加审批流**：最严谨，但当前没有审批中心，成本过高。

**选择 B 的原因**：促销是价格承诺，必须可追溯；“复制为草稿”把多出来的那一步变成一次点击。

### Q6. 数据库升级：重建还是增量迁移？

- **A. 每次改 schema 都重建库**：简单；但会丢数据，且生产不可接受。**不选**。
- **B. 增量迁移 `V3__store_admin.sql`（已选）**：不删数据，Flyway 记录版本；已在本机验证 V3 成功。
- **C. 改 baseline**：会让旧库 checksum 失配，启动即炸。**禁止**。

**选择 B 的原因**：当前库已有业务数据；增量迁移是唯一既能升级又不丢数据的路径。
注意：**V1/V2 squash 之前的旧库**仍不支持原地升级，需要重建（已写进交接）。

### Q7. 跨云迁移做不做？

- **A. 本批做**：需要对象存储/数据库/消息队列三套迁移与回滚演练，工期不可控。**不做**。
- **B. 只写规划（已选）**：明确前置条件、回滚与触发条件，避免以后把“改 endpoint”当迁移。
- **C. 完全不提**：下次又会从零讨论。**不选**。

**选择 B 的原因**：用户明确“先作为将来的规划”，规划落地成 `docs/CROSS_CLOUD_MIGRATION_PLAN.md`，
代码层不引入半成品。
