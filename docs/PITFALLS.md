# 踩过的坑（强制自查清单）

> 每次动手前后逐条对照。**同一坑不允许踩第三次**；本文件由实际事故记录，不是想象。

## 1. 陈旧产物（已踩 4 次）

| 现象 | 原因 | 规则 |
|---|---|---|
| 改了后端但接口行为没变 | 只 `mvn test`（编译）未 `mvn package`，跑的旧 jar | **验证任何 HTTP 行为前必须 `package` 并重启** |
| 改了前端但页面没变 | 未 `npm run build`，跑的是 `.output` 旧产物 | 改前端后先 build 再起服务 |
| 改了代码但测试仍通过 | 测试类未重新编译（增量编译异常） | 关键用例加 `-Dtest=X` 单跑确认输出 |

## 2. 补丁静默跳过（已踩 3 次）

| 现象 | 原因 | 规则 |
|---|---|---|
| 脚本打印"成功"，文件没变 | 用"关键字是否存在"做幂等判断，判断写错 | **补丁前 `assert 锚点 in 内容`**，补丁后 `grep -c` 命中数 ≥1 |
| 改到的位置不是预期函数 | 锚点文本太通用（如 `async function`） | 锚点必须含函数名与唯一上下文 |

## 3. Vue 模板陷阱（已踩 2 次）

| 现象 | 原因 | 规则 |
|---|---|---|
| 弹窗渲染成"每行一个" | `replace('</template>')` 命中表格插槽的第一个 | **改模板只用最后一个 `</template>` 或加唯一锚点** |
| `v-loading` 无效 | 顾客端未引入 Element Plus | 顾客端用显式状态（`loading` ref）渲染，不用 Element Plus 指令 |

## 4. 模块边界（已踩 2 次，都被测试拦住）

| 现象 | 原因 | 规则 |
|---|---|---|
| `Cycle detected: Slice order -> ...` | order → payment 反向依赖 | 新接口先想清楚属于哪个模块；跨模块用事件或注册制 |
| `platform depends on non-exposed type` | platform 直接 import 业务实体 | platform 只放接口/注册表，业务模块自注册 |

## 5. 类型与枚举（已踩 2 次）

| 现象 | 原因 | 规则 |
|---|---|---|
| `No enum constant FulfillmentType.SHIP` | 把接口的 `fulfillmentMode` 当成行内枚举 | 枚举值以代码为准，`grep enum` 后再写 |
| `Illegal base64 character` | 密钥格式臆测 | 外部输入格式先看校验代码 |

## 6. 数据与测试夹具（已踩多次）

| 现象 | 原因 | 规则 |
|---|---|---|
| 外键约束失败 | 用裸 UUID 造数据 | 按真实依赖顺序造：product → sku → member → order → 子表 |
| 测试互相污染（AK 残留） | 共享库 + 未清理 | 用例开头清理涉及的设置键 |
| 调度注册表测试失败 | 新增任务未登记断言 | 新增 `ScheduledJob` 必须更新 `ScheduledTaskServiceTest` |

## 7. 金额与口径（高风险）

| 现象 | 原因 | 规则 |
|---|---|---|
| 佣金"虚高余额" | 对 `commission_amount` 直接求和，未扣 `consumed_amount` | 可提现 = `commission_amount - consumed_amount` |
| 部分退款金额对不上 | 尾差分配不确定（按 id 排序） | 尾差给"剩余金额最大"的行，保证可复现 |
| 券被用两次 | 只校验未过期，未校验状态 | 核销必须条件更新 `status='UNUSED'` |

## 8. 演示/生产隔离

| 现象 | 原因 | 规则 |
|---|---|---|
| 生产把短信记成"已发送" | mock sender 永远注册 | prod 不注册 mock；未配置就明确失败 |
| 缺配置启动失败 | 早期 fail-fast 设计 | **不能阻断启动**（否则进不了后台配置）；改为运行时拒绝 + 后台可见 |

## 9. 清单与报告

| 现象 | 原因 | 规则 |
|---|---|---|
| 清单条目与代码不符（D3/D9） | 登记前没读代码 | **登记前 grep 事实**，写清出处 |
| 报告固定"三条" | 把结论凑整 | 按真实数量报，不设上限 |
| 声称完成但没验证 | 把"构建通过"当"能用" | 分列：已做并验证 / 已做未验证 / 未做 |

## 10. 时间与时区（本轮新增）

| 现象 | 原因 | 规则 |
|---|---|---|
| 订单号时间跳 8 小时 | `LocalDateTime.now()` 隐式用服务器 TZ | 生成时间戳必须**显式传时区**（`Ids.configureZone` + `app.timezone`） |
| 生日错一天 | 用服务器日期判断"今天" | 按**主体所在时区**算本地日期 |
| 对账对不上 | 管理端用浏览器本地时区显示 | 管理端固定东八，顾客端按会员时区 |

补充：数据库时间列统一用 `TIMESTAMPTZ`（存绝对时刻，与服务器时区无关）；
例外是 JaVers 自带表 `commit_date TIMESTAMP`（库自带 schema，未改）。

## 11. 两套 token 不能混用（本轮新增）

| 现象 | 原因 | 规则 |
|---|---|---|
| 公开接口 401 | 带着 staff token 调 `/api/v1/**`，会员过滤器把无效会员 token 当未登录 | 调公开接口**不要带** staff token；两套鉴权各走各的过滤器 |
| 后台接口 401 | 带会员 token 调 `/admin/**` | 同上，反之亦然 |

## 12. 拼接 SQL 时分隔符丢失（已踩 2 次）

| 现象 | 原因 | 规则 |
|---|---|---|
| `ORDER BY total_spent DESCLIMIT ?` | 三引号拼接时没保留换行/空格 | 拼接片段**以空格结尾**，或整段用 `String.format`；改完立刻用测试打一次真实查询 |

## 13. 新增导出资源/接口后必须重新打包（第 6 次同类）

| 现象 | 原因 | 规则 |
|---|---|---|
| E2E 报 `不支持的导出资源: sku_cost`，页面显示 FAILED | 后端跑的是**旧 jar** | 改后端任何可观测行为后：`mvn package` → 停旧进程 → 起新 jar → 再验 |
