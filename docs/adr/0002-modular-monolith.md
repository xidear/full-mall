# ADR-0002: 模块化单体 + api/worker/ws 三进程

- 状态：Accepted
- 日期：2026-10-18

## 背景

系统早期需要快速交付，同时又要为客服、搜索、支付回调等独立扩展留出边界。直接上微服务会引入分布式事务、链路调试和运维复杂度。

## 决策

- 使用单个 Spring Boot 应用，按业务模块分包，由 Spring Modulith 校验依赖方向。
- 同一 jar 通过 profile 启动三种角色：
  - `api`：HTTP API。
  - `worker`：支付对账、供应商同步、通知、索引、超时任务。
  - `ws`：客服 WebSocket 网关。
- 模块间只通过公开接口和领域事件通信；跨模块异步事件使用 Transactional Outbox。
- 只有出现明确瓶颈时才拆分服务；优先拆客服、搜索、支付回调。

## 后果

- 本地调试只需一个代码库、一个数据库，链路清晰。
- 三个进程可独立扩缩容，部署仍共享镜像。
- 需要 discipline：禁止跨模块直接访问对方表或内部类。

## 替代方案

- 单体单进程：最简单，但 WebSocket 和后台任务会争抢资源。
- 微服务：边界清晰但早期成本过高。
