# 客户资料导入指南（AI 客服）

> 这份文档**直接发给客户**。客户按这里给资料，导入成功率和回答准确率最高。

## 1. 最好给什么（按推荐度）

| 推荐度 | 格式 | 说明 | 我们能拿到什么 |
|---|---|---|---|
| ★★★ | **Excel / CSV**（一件商品一行） | 商品参数、价格、规格统一表格 | 字段级准确值，可直接做结构化问答 |
| ★★★ | **Markdown / TXT**（问答对） | `问题 / 答案` 两列或用 `Q:`/`A:` | 最贴近客服话术，命中率最高 |
| ★★ | **Word（.docx）** | 售后政策、服务条款、操作手册 | 正文段落（表格会被拍平成文本） |
| ★★ | **PDF（文本版）** | 说明书、政策文件 | 正文段落；**扫描版无文字层，需先 OCR** |
| ★ | **网页链接** | 现行帮助中心 | 正文；导航/广告会被过滤 |
| ✗ | 图片、扫描件、视频 | 无法直接读文字 | 请提供文字版或先 OCR |
| ✗ | 加密 PDF / 需要登录的链接 | 解析失败 | 请解密或导出为普通 PDF |

**一次给多少**：单文件 ≤ 50 MB；单次导入 ≤ 200 个文件；文本总量建议 ≤ 20 MB（超出会分批）。

## 2. 商品表模板（最推荐）

```csv
skuCode,title,specs,price,currency,stockStatus,warranty,notes
MILK-500,全脂鲜牛奶 500ml,"容量:500ml;保质期:21天;储存:2-6℃冷藏",39.90,CNY,有货,不支持无理由退货,"开封后请24小时内饮用"
```

- `skuCode` 必须与系统里的 SKU 编码一致（否则只能作为通用知识，不能绑定商品）；
- `specs` 用 `键:值;键:值` 分号分隔，便于我们切成结构化字段；
- `notes` 写"顾客最常问的注意点"，这部分对回答质量提升最大。

## 3. 问答对模板

```markdown
Q: 鲜奶可以退货吗？
A: 鲜奶属于生鲜商品，未开封且签收 24 小时内可申请退货；已开封不支持退货。

Q: 多久发货？
A: 现货商品在付款后 24 小时内发出；预售商品以商品页标注为准。
```

- 一个问题一条，答案 ≤ 200 字（太长会被切分，反而降低命中）；
- 政策类答案**必须写清条件**（时限、是否开封、是否需凭证），否则 AI 只能照抄模糊表述。

## 4. 我们怎么用这些资料（客户可核对）

1. **解析**：按文件类型抽文本（PDF/Word 用 Apache Tika，表格按行读）；
2. **切分**：按语义段切，单块 ≤ 500 字；商品一行一块，问答一问一块；
3. **入库**：每块记录来源（文件名 / SKU / 页码或行号），**改一次重建一次**；
4. **检索**：生产用向量 + 关键词混合；演示模式用关键词（无需 GPU）；
5. **回答**：只依据检索到的块作答，**附带来源**；没有依据就说"没查到，转人工"。

## 5. 导入失败时你会看到什么

| 提示 | 原因 | 处理 |
|---|---|---|
| `UNSUPPORTED_FORMAT` | 图片/扫描件/压缩包 | 换文字版 |
| `EMPTY_DOCUMENT` | 解析后没有文字（扫描版 PDF 常见） | 提供文字版或 OCR 后重传 |
| `FILE_TOO_LARGE` | 超过 50 MB | 拆分 |
| `SKU_NOT_FOUND`（警告） | 表格里的 skuCode 系统里没有 | 先建商品，或去掉该列作为通用知识 |
| `ROW_REJECTED`（行级） | 该行字段缺失/格式不对 | 按提示行号修正后重传 |

**导入不会静默跳过坏行**：每一行的问题都会列出来。

## 6. 演示模式 vs 生产模式

| 项 | 演示模式（`app.ai.mode=demo`） | 生产模式（`app.ai.mode=prod`） |
|---|---|---|
| 资料 | 内置 mock 商品与问答 | 客户真实资料 |
| 检索 | 关键词（无需 GPU） | 向量 + 关键词 |
| 回答 | **抽取原文**（不改写） | 模型生成，受约束检查 |
| 约束 | 基础约束（来源/越权/金额） | 同左 + 更严格的事实一致性检查 |

演示模式的意义是让客户看到"资料怎么变成回答"，不是假装模型很聪明。
