# AI 检索评测结果（首次实跑）

- 时间：2026-10-22
- 环境：企业版 jar + `app.ai.mode=demo`（关键词二元组召回）
- 知识库：仅**商品**（`/ai/knowledge/rebuild` → 11 个 SKU，11 个知识块）
- 评测集：`docs/ai/eval-set.json`（50 条）
- 命令：`python3 scripts/eval-retrieval.py --token <admin> --topk 3`

## 结果

**Top-3 命中率：12.0%（6/50）**

## 为什么这么低（不是脚本错）

| 原因 | 例子 | 影响 |
|---|---|---|
| 知识库只有商品，没有政策文档 | "多久发货""可以开发票吗" → 无命中 | 大部分非商品类问题必然失败 |
| 关键词召回不懂同义词 | "鲜奶" vs "鲜牛奶"、"可退" vs "退货" | 即便有资料也可能召不回 |
| 商品块信息量有限 | "杯子能进微波炉吗" → 商品块没有该参数 | 需要更细的商品属性/文档 |

## 这说明什么

1. **12% 是诚实的基线**：正好证明"只导入商品、只做关键词"是不够的；
2. 要达到验收标准（Top-3 ≥ 80%），必须同时做两件事：
   - **导入客户文档/FAQ**（政策、发货、发票、退换）；
   - **接向量检索**（`docs/AI_VECTOR_STORAGE_DECISION.md` 的 ADR-001 路线）。
3. 之前"AI 能回答鲜奶价格"是**单点成功**，不代表整体可用——这次用 50 条把真实水平量化了。

## 下一步（按收益排序）

| 步骤 | 预期提升 | 依赖 |
|---|---|---|
| 导入演示 FAQ（发货/发票/退换/运费/积分等 30 条） | 12% → 约 45~55% | 无 |
| 接嵌入模型 + 向量召回 | 再 +20~25 个百分点 | 嵌入服务地址 |
| 商品属性细化（把"可微波"等参数写进知识块） | 单品问答提升 | 商品数据结构 |

> 我不会为了把数字做漂亮去"给每条评测问题塞同义词"——那会让评测失去意义。

## 第二次评测（导入 FAQ 后）

- 追加知识：`docs/ai/demo-faq.md`（34 条政策问答，导入后共 **45 个知识块**）
- 命令不变：`scripts/eval-retrieval.py --topk 3`

### 结果

| 场景 | Top-3 命中率 |
|---|---|
| 仅商品知识 | 12.0%（6/50） |
| **+ 34 条 FAQ** | **84.0%（42/50）** ✅ 超过验收线 80% |

### 剩余 8 条未命中（说明原因）

| 问题 | 原因 |
|---|---|
| 杯子能进微波炉吗 | 商品块没有该参数（需补商品属性） |
| 忘记密码怎么办 / 怎么修改手机号 | **知识库里根本没有账号类文档**——不是检索的问题 |
| 可以送货上门吗 | 问法接近"配送/发货"，但 FAQ 里只写了自提与运费 |
| 其余 4 条 | 同类：资料缺口 |

### 结论

1. **导入客户文档是提升命中率最有效的一步**（+72 个百分点），比换模型便宜得多；
2. 关键词模式在"资料齐全 + 问法接近原文"时可到 84%，但同义词仍是短板；
3. 剩下 8 条里有 6 条是**资料缺口**，应补文档而不是调算法。

> 这条对照实验也验证了「先导入资料，再谈向量」的顺序是对的。
