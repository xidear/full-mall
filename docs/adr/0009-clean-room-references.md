# ADR-0009: Clean-room 参考策略

- 状态：Accepted
- 日期：2026-10-18

## 背景

成熟开源商城可以显著降低领域建模风险，但直接 fork 或复制代码会继承架构、许可证和维护负担，也不符合“自研但不抄袭”的目标。

## 决策

- 不 fork 任何大商城作为核心。
- 参考项目用于：
  - 领域词汇和模块边界。
  - 公开 API、用户文档、行为基准。
  - 产品 UX 和功能对照。
- 禁止：
  - 复制代码、UI、文案、图标、数据库 schema 原文。
  - 将 AGPL/GPL 代码链接进核心。
  - 逐行对照参考项目实现。
- 流程：
  1. 先写 ADR/ERD/OpenAPI/功能对照表。
  2. 建立 `docs/references/` 登记项目、版本、许可证、借鉴点、未复用内容。
  3. GPL/AGPL 只读文档和公开行为；MIT/BSD 可读源码但默认重写。
  4. CI 做 License/SBOM 扫描；代码评审检查来源。
- 需要电子签名、支付编排等能力时，独立部署成熟服务并通过 API 集成。

## 后果

- 初期需要投入 3–5 天做参考调研和对照表。
- 代码来源可审计，降低许可证和知识产权风险。
- 不追求与参考项目 100% 功能一致，按自己的业务优先级取舍。
