# ADR-0011: 多主题模板与小程序图形化配置

- 状态：Accepted
- 日期：2026-10-18

## 背景

同一套商城代码需要服务不同行业和品牌：PC 商城需要“通用零售”和“机械设备/工业品”两种视觉与信息密度；小程序需要多种风格，并允许运营通过图形化界面微调颜色、圆角、布局和首页文案。参考 CRMEB 的模板/DIY 思路，但不能复制其代码、UI、文案或数据结构。

## 决策

- 建立共享 `@fullmall/theme` 包，定义 `ThemeConfig`、预设和 CSS 变量输出。
- PC 端：
  - 预设：`mall`（通用商城）、`industrial`（机械/工业）、`fresh`、`minimal`。
  - 通过 `NUXT_PUBLIC_THEME` 或 URL `?theme=` 选择；运行时写入 CSS 变量与 `data-theme`。
  - 模板差异通过变量和少量结构样式实现，不复制整页代码。
- 小程序端：
  - 复用同一套 `ThemeConfig` 预设。
  - 运营后台提供“主题工作室”：预设、颜色、圆角、字号、卡片风格、商品布局、首页 Banner 文案。
  - 所有输入为颜色选择器、滑块、下拉框、开关，不要求手填 JSON/逗号字符串。
  - 配置可导出为小程序主题 JSON；后续接入持久化 API 与页面级 DIY 配置。
- 模板/主题配置只影响表现层，不改变价格、库存、履约和权限规则。

## 后果

- 主题 token 成为前后端共同契约的一部分；新增主题不需要复制页面。
- 需要处理暗色主题的可读性、图片对比度和品牌色对比度。
- 小程序图形化配置后续需要服务端存储、版本发布和回滚。
- 参考 CRMEB 只学习“预设 + 可视化配置 + 预览”的产品思路，不复制代码/UI。

## 后续

- 页面级 DIY：Banner、商品分组、楼层、活动位的 schema 化配置。
- 主题版本化、预览环境、发布/回滚、按市场/门店覆盖。
- 增加对比度/可访问性检查。
