# ADR-0006: 多模式履约与订单拆单

- 状态：Accepted
- 日期：2026-10-18

## 背景

订单可能同时包含自营仓库存、门店库存、供应商代发商品和门店自提商品。不同履约源的时效、运费、库存和售后责任不同。

## 决策

- 订单（Order）与履约单（Fulfillment Order）分离；一个订单可拆成多个履约单。
- 履约类型：
  - `WAREHOUSE_SHIP`
  - `STORE_SHIP`
  - `SUPPLIER_DROPSHIP`
  - `STORE_PICKUP`
- 履约分配引擎按市场、库存、仓库优先级、门店距离、供应商 SLA、成本、保质期和拆单最少化选择来源；支持人工改派。
- 运费按包裹分摊；支持部分发货、部分退款、部分售后。
- 自提单在门店库存预占，生成提货码；超时释放并触发退款。
- 供应商代发通过 `/open/v1` 推单，要求接单/发货/轨迹回传；超时自动升级。

## 后果

- 订单状态机和售后逻辑更复杂，但符合真实业务。
- 需要履约单级别的物流、退款和客服上下文。
- 拆单规则必须可视化配置和可审计。

## 替代方案

- 一单一包裹：无法支持多仓、门店和供应商混合订单。
