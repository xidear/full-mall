# 跨云迁移：规划（暂不实施）

> 状态：**未来规划，2026-10-31 明确不做**。本文只记录约束与迁移前置条件，避免以后把“迁移”
> 误当成“改个 `endpoint` 就行”。

## 为什么现在不做

- 当前部署是单机 Docker Compose（Postgres / Valkey / RabbitMQ / OpenSearch / SeaweedFS + API）。
- 跨云迁移需要对象存储、数据库、消息队列三套数据面的迁移与回滚方案，以及 DNS/证书切换窗口；
  在当前阶段（功能补齐、单机可复现）投入产出比低。
- 素材存储已经抽象为 `storage` 集成（local / COS / 七牛），迁移脚本
  `scripts/migrate-storage.py --verify` 已能核对“库内记录 vs 实际文件”，这是迁移的第一步，
  不等于迁移完成。

## 迁移前置条件（按顺序）

1. **数据面盘点**：Postgres 全库、SeaweedFS 对象（或外部 COS/七牛桶）、导出文件、日志保留策略。
2. **一致性快照**：数据库 `pg_dump` + 对象存储清单（key、size、etag、sha256）；两者用
   `asset`/`export` 表关联核对，缺一不可上线。
3. **双写或停机窗口二选一**：
   - 双写：要求所有写入走 outbox + 幂等键，且对象存储支持跨云复制；
   - 停机：给出可接受的中断时长与回滚点（当前业务可接受停机窗口未确认）。
4. **回滚演练**：在新环境完成一次“写入 → 导出 → 回滚到旧环境”的演练，记录耗时与丢失量。
5. **DNS/证书**：`company.binnarui.com:15443` 的证书签发方式（DNS-01）需在新环境复现，
   并保留旧环境 24 小时只读。
6. **验收**：订单、库存、优惠券核销、会员余额四类数据逐项对账；AI 供应商与集成配置单独导出导入
   （密钥由 `SecretCipher` 加密，迁移时必须带同一把 `APP_SECRET_KEY`，否则密文不可解）。

## 明确不在本期范围

- 多云双活、跨云读写分离、对象存储双向同步。
- 数据库逻辑复制/CDC 接入。
- 迁移期间的价格与税费重算（迁移只搬运事实，不重算历史订单）。

## 触发条件（什么时候再启动）

- 单机容量（CPU/磁盘/连接数）接近上限，或需要跨区域低延迟；
- 合规要求数据落地到特定区域；
- 对象存储/数据库需要独立扩缩容与备份 SLA。
