# Full Mall 开发计划 v2

> 版本：2.0
> 日期：2026-10-19
> 基线：当前 `main`（Flyway v21，Playwright 10/10，后端 38 测试 / 36 通过 / 2 skipped）
> 关联：`requirements/PRODUCT_REQUIREMENTS_V2.md`、`requirements/TECHNICAL_ARCHITECTURE_V2.md`、`requirements/TECHNOLOGY_DECISIONS_V2.md`

## 0. 计划说明

- 本计划覆盖用户 2026-10-19 提出的全部新增需求。
- 估算按 **4–6 人团队**：后端 2–3、前端 1–2、QA/DevOps 1、产品/设计 0.5–1；2–3 人团队按 1.8–2.5 倍时间估算。
- 估算单位为人周（pw），包含开发、测试、文档、验收，不含外部资质/商户开户等待。
- 现有 POS、库存、订单、供应商基础 API、仓储基础、RBAC、售后、会员等级、分销、客服工作台、促销基础已实现；本计划在现有基础上演进，不重写。
- 每个阶段有 Gate；Gate 不通过不进入下一阶段。

## 2. P0：仓库策略与公共底座（2–3 周）

### 目标

让后续所有模块共享同一套模型/控制器/权限/审计/开关/API 版本能力，并先完成成熟方案选型。

### 交付

- **技术选型 spike + ADR**：Spring Security、JPA/Hibernate、OPA/Casbin、Drools/Easy Rules、Unleash/FF4j、Flowable、Spring AI/LangChain4j、Tolgee；结论写入 `TECHNOLOGY_DECISIONS_V2.md`。
- `AGENTS.md` 推送策略：默认只推 Gitea；GitHub/Gitee/三端必须明确指定。
- `gitea-dev` 分支：包含 `.env`、本地开发配置；GitHub `main` 不含任何私密配置。
- 功能开关采用成熟组件（Unleash 或 FF4j）或在其上的薄封装；供应商、POS 卖货、POS 自提、站点状态。
- `BaseEntity/BaseScopedService/BaseCrudController/ScopeResolver`；行级范围用 JPA Specification/Hibernate Filter，不建字段权限框架。
- 审计采用 JaVers；导出脱敏基础；Spring Security 方法授权。
- API 版本骨架：`/open/v1` 契约测试、springdoc/OpenAPI 生成、Changelog 模板。
- CI：后端测试、前端构建、Playwright、secret scan、OpenAPI diff。

### 验收

- 供应商 A 无法读写供应商 B 的任何数据。
- 越权操作/行返回 403/404；若启用 ERP 字段策略，越权字段返回 400/403，不静默丢弃。
- 关闭供应商开关后 API/Web/登录 403/503；站点关闭后前台不可用但支付回调可用。
- `gitea-dev` 可直接启动；`main` 不含 `.env`/密钥。
- 选型文档包含候选、许可证、放弃理由，未记录的“自研”不得进入开发。

## 3. P1：供应商 API、门户与待办（3–4 周）

### 交付

- `/open/v1` 统一 API：订单、库存、发货、结算、退货、待办、Webhook。
- 认证：Bearer token + IP allowlist + HMAC；token 轮换/吊销；限流/nonce/重放。
- 供应商门户改为调用 `/open/v1`，去掉独立业务 API。
- 待办中心：拉取 + WSS 增量 + seq/ack + 断线补拉 + 未读数。
- 事件：缺货、待发货、订单变更、结算、退货；超时提醒。
- 版本化文档站点：OpenAPI、错误码、签名示例、CSV 模板、Webhook 事件、弃用策略。
- 风险预警：异常 IP、401/403、nonce 重放、签名失败、批量拉取、Webhook 失败。

### 验收

- 供应商自建客户端与门户使用同一契约。
- 断网重连后待办不丢不重。
- 供应商 A 不能访问 B；token 吊销立即生效。
- 文档与实现一致性 CI 通过。

## 4. P2：供应商结算、CSV、Webhook、退货（3–4 周）

### 交付

- 结算单：周期、订单、扣款、退货冲减、应付、状态、争议。
- CSV 导入导出：订单/结算/退货；表头/类型/金额/重复/业务键校验；错误行号与原因。
- Webhook：订阅、HMAC、重试/退避、投递记录、手动重放、死信、告警。
- 退货对账：申请、收货、质检结果、补发/退款/报损、供应商责任、结算冲减。
- 供应商结算数据范围：供应商只看自己；平台运营按权限。

### 验收

- 结算金额与订单/退款/佣金对账一致。
- Webhook 连续失败进入死信并告警；重放幂等。
- CSV 部分错误不产生部分成功。
- 退货差异可追踪到结算。

## 5. P3：自营 ERP 与售后补发（3–4 周）

### 交付

- 采购单（不做多级审批）、到货预约、收货、质检、上架批次。
- 盘点单提交/差异复核/审批/调整流水；报损单原因/批次/成本/审批。
- 售后换货：审核、收货、质检、补发履约单、库存预占/扣减、物流回传。
- 质检不合格：隔离/报损/退供；成本与供应商结算冲减。
- ERP/OA/Admin 操作日志与权限。

### 验收

- 采购到上架全链路库存准确；FEFO 生效。
- 盘点审批后库存流水可追溯；报损不影响可用库存错误。
- 换货补发不超卖、不重复扣库存。
- 供应商侧不被迫使用采购/质检模块。

## 6. P4：线上会员与促销引擎（4–5 周）

### 交付

- 线上会员登录（手机 OTP；预留微信/支付宝）；会员主体与 POS 共用。
- 线上等级折扣、积分倍率、成长值、生日礼；匿名不享受。
- 促销规则引擎：满减、满折、满赠、买赠、秒杀、拼团、优惠券、会员折扣、砍价。
- 叠加/互斥/优先级/最优价；试算 API；优惠明细。
- 渠道隔离：ONLINE / POS / PICKUP；POS 自提不重算线上优惠。
- 退款/取消/拼团失败回滚促销名额与积分。
- 后台规则构建器（无 JSON/逗号字符串）。

### 验收

- 同一购物车在线上/POS 命中不同活动集合。
- 最优价计算与手工核对一致；冲突规则有明确优先级。
- 秒杀/拼团名额并发不超卖。
- POS 自提不产生二次折扣。
- 线上会员成长/生日礼只对登录会员生效。

## 7. P5：真实支付与对账（4–5 周）

### 交付

- `PaymentConnector` 适配器：微信、支付宝、银联、聚合收单。
- 后台凭证配置：商户号、AppID、API v3 key、证书、私钥、平台公钥、回调地址；加密/掩码/轮换/审计。
- Webhook 验签、幂等 inbox、重复/乱序、退款/部分退款。
- 对账文件导入：渠道 vs 订单 vs 退款 vs 结算；差异分类/处理/日结。
- 演示 Mock；生产缺配置 fail-fast；拼团失败退款走真实适配器。

### 验收

- 四类支付至少各一条沙箱/联调通过（取决于商户资质）。
- 重复回调不重复记账；退款金额一致。
- 对账差异可定位、可处理。
- 生产缺凭证明确报错，不回退 Mock。

## 8. P6：客服实时化与 AI（4–5 周）

### 交付

- WebSocket 网关：ticket、seq/ack、心跳、断线补拉。
- 分组/技能/语言/班次路由；离线自动转单；无人在线转 Bot/排队。
- 消息：文本/图片/文件/商品/订单/物流/帮助链接/系统消息。
- 已读、正在输入、关闭/重开、转单、满意度。
- AI `BotEngine`：demo Mock；prod 缺配置报错；RAG 知识库、引用、工具调用、PII/注入防护。
- SLA/质检：首响、解决时长、超时升级、抽检、评分、AI 摘要。
- 顾客侧聊天入口（PC/移动）。

### 验收

- 断网重连消息不丢不重。
- 客服离线自动转单可追踪；主管跨组可见。
- AI 回答有引用；工具调用鉴权；生产缺配置明确报错。
- 附件类型/大小/病毒扫描生效。

## 9. P7：多语言、多币种、素材库（4–6 周）

### 交付

- en/es/fr/ar 语言包与 RTL；ICU；语言切换/回退。
- AI 翻译 + 人工校对流程、术语表、翻译记忆、审校状态。
- CNY/HKD/MOP/TWD 价格表、汇率快照、舍入、前台显示。
- 港澳台支付/物流适配器代码 + Mock；生产缺 AK/token 报错。
- 素材库：公共/个人、文件夹/标签、上传/预览/替换、引用统计。
- 软删除/恢复/彻底删除（引用检查）；素材版本。
- 存储 SPI：Local/SeaweedFS/S3/七牛/阿里云 OSS；切换迁移/双读/回滚。

### 验收

- ar 页面 RTL 布局正确，无左右写死样式。
- 翻译未审校不能上线法律/支付文案。
- 切换存储后旧素材可访问；迁移校验 hash；回滚可用。
- 被引用素材不能物理删除。

## 10. P8：数据权限、审计、风险、门店授权（3–4 周）

### 交付

- 客服主管跨组视图；导出脱敏/范围/水印/文件过期；供应商结算范围。
- ERP 角色可见性（按需）：页面/操作/行级默认；字段级仅在明确需要时用 OPA/Casbin 策略 + DTO 投影，不自建字段矩阵。
- 操作日志覆盖：登录、权限、价格、库存、订单、退款、结算、开关、密钥、导出、供应商写操作。
- 风险预警：异常登录、越权、签名失败、批量导出、结算/支付差异、Webhook 失败、库存异常。
- 店长改价/作废授权；交接班审核；员工排班。
- 线下扫码/碰一碰 Mock；生产缺配置报错。

### 验收

- 越权负向测试全部通过；导出无越权字段。
- 关键操作 100% 有审计；日志不可篡改。
- 改价/作废无授权不能完成；交接差异可追溯。
- 排班与开班关联。

## 13. 风险

1. **全 ORM 重写风险**：禁止大爆炸；新模块用新范式，存量逐步迁移。
2. **字段可见性误当安全边界**：默认 DTO 投影；ERP 需要时用 OPA/Casbin + 输入校验，不自建字段矩阵。
3. **供应商门户双 API**：必须统一 `/open/v1`，否则权限/文档/审计分叉。
4. **POS 与线上促销混用**：渠道隔离不做会导致自提二次优惠/对账错误。
5. **支付生产回退 Mock**：必须 fail-fast；否则假成功。
6. **AI 生产无配置**：必须报错，不返回空答案。
7. **云存储切换断链**：必须迁移/双读/回滚，不做“直接改 base URL”。
8. **软删除被绕过**：引用检查 + 权限 + 审计。
9. **站点关闭误伤支付回调**：白名单放行回调/健康检查/内部任务。
10. **Gitea 私密配置误推 GitHub**：gitea-dev 分支隔离 + AGENTS 规则 + CI secret scan。
